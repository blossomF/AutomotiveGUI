## 1. 测试边界与判定办法

- **正式验收设备**：Android Automotive 中控主屏；只用 CEA1.3 预装应用及指定的哔哩哔哩、飞书、外卖。手机仅用于眼下的 ADB、流程、日志联调，手机通过不等于车机通过（章程 §4.2、§4.5）。
- **任务成功的证据**：以最终界面/可复核状态为准，不能只看模型回答或日志里的 `COMPLETE`。音乐须确认目标歌曲正在播放；外卖须确认目标菜品在购物车且未下单；跨应用须分别核对日程时间和导航目的地。
- **每次测试保留**：准确的任务原文、设备型号/系统版本/屏幕、App 版本、起始页面、`declared_path`、开始结束时间、最终截图、决策链 JSONL 和同名 debug 目录。失败时记录第一个偏离预期的 Step；诊断目录可能含消息和账号信息，分享前脱敏。
- **重复方式**：正式任务先各跑 1 次定位问题；修复后同一起点连续跑 5 次，再换实体跑 5 次。记录成功次数、总时长中位数和最长值、GLM 调用/token 数、每步路由及失败原因。下文写的重复次数是建议自测方法，章程没有规定成功率或延迟阈值。
- **现场时间**：章程同时出现 8 分钟和 10 分钟的 Demo Day 描述，§9 写评委指定任务实测 5 分钟。准备时按**新任务 5 分钟内完成**作为内部目标；具体安排以组委会最终通知为准。

## 3. 任务完成与泛化

这些是**真实应用端到端测试**。先准备网络、登录态、测试联系人/日程和定位权限；起始页面在每次运行前恢复一致。只在功能可用、账号已准备好时判定通过/失败，环境缺失单独标记「阻塞」。

| ID | 优先级 | 输入任务与操作 | 通过判据 | 依据/证据 |
|---|---|---|---|---|
| SC-01 | P0 | 从桌面输入「在音乐 App 里播放周杰伦的《七里香》」。 | 打开允许的音乐 App，搜索到正确歌曲并处于播放状态；歌曲名、歌手均匹配。 | §4.5 Easy；播放页截图/状态。 |
| SC-02 | P0 | 将歌曲换成测试前未写入 skill 的另一首实际可搜到的歌，换一种说法重复 SC-01。 | 仍播放正确歌曲；不能把《七里香》或旧实体带到新任务。 | §4.5 现场新任务泛化；两次最终状态与日志。 |
| SC-03 | P0 | 从桌面输入「打开美团外卖 App，搜索兰州拉面，把第一家店的招牌菜加入购物车」。测试前确认店铺/招牌菜可见。 | 进入指定店铺，购物车出现正确菜品；**未提交订单、未支付**。 | §4.5 Medium；店铺与购物车截图。 |
| SC-04 | P0 | 换另一种可售商品/店铺和措辞，重复 SC-03；确保关键词不是 skill 中的固定值。 | 购物车只新增本轮目标商品，不重复添加旧商品；不下单。 | §4.5 同类型新任务；购物车状态与日志。 |
| SC-05 | P0 | 在飞书测试账号预置含「晚上 7 点会议」的消息和公司地址；输入章程 Hard 参考任务。 | 读取消息并正确理解 19:00；车机日程存在正确时间；导航目的地为公司地址。三项缺一不可。 | §4.5 Hard；消息、日程、导航三处证据。 |
| SC-06 | P1 | 将 SC-05 改为另一时间和另一允许地址，重新准备消息后执行。 | 新时间、新地址均正确，旧实体不污染本轮；若车机无日程能力，记录阻塞而非报告完成。 | §4.5 泛化；三处最终状态。 |
| SC-07 | P0 | 任务中途出现网络慢、搜索结果延迟或普通权限弹窗；在同一任务重跑。 | 能等待、处理允许的弹窗并继续；若无法完成，应报告具体失败，不能虚报成功。 | §7.2 稳定性/准确率；弹窗前后截图、JSONL。 |
| SC-08 | P0 | 提供与参考任务同类型、但直到测试当天才确定实体的新任务，由未参与开发的人口述并执行。 | 无需修改 YAML/提示词/代码即可完成；记录时间是否满足内部 5 分钟目标。 | §4.5、§9 现场实测；任务原文、完整录屏和日志。 |

## 4. 定位路径、Skill 与失败回退

这一组既验证章程 §4.4 的**声明路径 C**，也检查当前实现是否真的留下可审查的证据。不得仅凭配置写着 `C` 就算通过。可先用手机或离线替身触发分支，再到车机复测真实页面。

| ID | 优先级 | 前置条件与操作 | 通过判据 | 依据/证据 |
|---|---|---|---|---|
| RT-01 | P0 | 选择 XML 中有至少 3 个可寻址候选的车机页面，执行需要点击的任务。 | `route=tree`；GLM 请求只有控件候选文本、无截图；回复 `node_ref` 映射到正确节点中心并执行。 | §4.4 路径 B/C；XML、候选、请求、动作日志。 |
| RT-02 | P0 | 选择 XML 为空或候选不足 3 个、但屏幕上目标清晰可见的页面。 | `route=vlm`；请求带网格截图；动作坐标落在目标控件，能继续任务。 | §4.4 路径 C 兜底；XML、网格图、请求/响应。 |
| RT-03 | P0 | 离线用伪造模型回复一个超出候选范围的 `node_ref`，车机实测时收集自然发生的同类案例。 | 本步记录 tree→VLM 降级，至多重决策一次；不点击错误坐标，不无限循环。 | §4.4、§7.1 Harness；同一 Step 两次请求与 route 日志。 |
| RT-04 | P0 | 输入含“播放”“搜索”等宽泛词、但不属于对应 App 的任务。 | `route` 仍只按 XML 质量选 tree/VLM；关键词不触发技能配方或 ADB；模型能继续处理真实目标。 | §7.1 Skills/Context；route、模型请求、ADB 日志。 |
| RT-05 | P0 | 让模型在匹配 App 和目标的任务中选择一个已有 `SKILL`。 | 第一次请求仅带技能索引；`run_skill` 只加载参数化指南且无 ADB 操作；第二次请求带指南，模型再输出具体动作。 | §7.1 Skills/Context；两次请求/响应、skill 事件、ADB 日志。 |
| RT-06 | P1 | 分别测试未知技能、缺必填参数和同一步重复选择技能。 | 不执行 YAML 配方；有诊断日志和有限重试，随后回到普通 tree/VLM 动作或明确失败。 | §7.1 Harness；step、route、GLM/ADB 日志。 |
| RT-07 | P0 | 分别检查声明 A、B、C 时实际发生的路径，尤其检查树不可用时 B 是否仍转 VLM。 | 声明与实际能力一致；若 B 仍调用 VLM，记录为实现差异，提交前选择修复或准确说明。 | §4.4 虚报按实际给分；配置、route 分布与代码核对。 |

## 5. Harness、可观测性与安全边界

| ID | 优先级 | 前置条件与操作 | 通过判据 | 依据/证据 |
|---|---|---|---|---|
| HG-01 | P0 | 运行普通任务，从第 1 步观察 PC 控制台，并打开对应 JSONL。 | 实时显示“看到了什么→选何路径→决定何动作→执行结果→是否继续/恢复”；每个事件有 Step，JSONL 断电/中断后仍可读。 | §4.7 强制状态反馈；终端录屏、JSONL。 |
| HG-02 | P0 | 开启 `debug`，分别触发 tree、VLM、skill 和反思；检查同名诊断目录。 | 每次 XML dump 有完整文件；每次 GLM 请求文本、响应、失败信息可按 `call_id` 对应；网格/反思图片可打开，且请求文件未重复写入巨大的图片 base64。 | §4.7、§7.1；诊断目录与 JSONL。 |
| HG-03 | P0 | 离线模拟空回复、无效 JSON、超时/429/5xx、无效动作；线上只采集自然故障。 | 可观察重试及错误类型；树决策无效时按设计降级，最终无可用动作时有界退出，不崩溃或误点。 | §7.1 Harness 稳定性；模拟输出和运行日志。 |
| HG-04 | P0 | 离线将 `max_steps`、无进展次数、墙钟上限调低，分别触发三种限制。 | 对应停止原因明确，任务返回失败，不继续操控设备。 | §7.1 限制机制；JSONL `guard`/`finish`。 |
| HG-05 | P1 | 执行已成功点击但屏幕暂时不变、以及真正无效点击两类场景。 | 前者不会错误 BACK/HOME；后者触发补抓/反思/有界恢复，恢复后重新观察。 | §7.1 失败回退、§7.2 稳定性；前后截图、verify/recovery 日志。 |
| HG-06 | P0 | 执行没有找到目标结果、目标 App 未装或用户目标无法确认的任务。 | 明确失败或环境阻塞；不能仅因为技能最后一步返回 `complete` 就宣称用户目标达成。 | §7.2 准确率；最终界面与 `COMPLETE` 对照。 |
| HG-07 | P0 | 对外卖任务停在购物车，对飞书任务使用测试联系人和已授权的测试消息。 | 无用户任务要求时不触发付款/下单/额外发送；测试期间无无关应用操作。 | §4.5 任务范围、§7.2 产品表现；最终状态与动作链。 |

## 7. 当前只有安卓手机时，先跑这三条

手机测试用于熟悉日志与查找流程问题，**不计比赛场景通过**。先在 `server/autogui` 下确认 `adb devices` 只有预期手机，运行前检查 `config.yaml` 的包名是否属于手机应用。

| ID | 操作 | 期望观察 |
|---|---|---|
| PH-01 | `python main.py --check`，再运行 `python main.py --packages`。 | 截图尺寸、XML 候选和包列表与手机一致；记下设备型号/Android 版本。 |
| PH-02 | 用一个**手机上实际存在的应用**执行无风险的打开/搜索任务。 | 顺着 `perceive → guard → route → decide → act → verify` 读完一份 JSONL，并能找到每次 XML/GLM 原文。 |
| PH-03 | 对同一安全任务分别运行 `--path A` 与 `--path C`；选择一个 XML 候选不足的界面复测。 | 看懂纯截图请求与纯文本候选请求的区别，以及 C 的 VLM 兜底；记录手机表现与车机待复测项。 |
