# `--check` 环境自检说明与网格优化

本文对应当前 `server/autogui/main.py::cmd_check`、`autogui/perception/grid.py` 和面板设置页。比赛场景仍以[大赛章程](CART%20Q3%20AI%20大赛章程%20v1.1a.md)为准；手机仅能做技术联调，正式任务需在车机中控验证。

## 从本次手机结果看什么

用户手机截图为 `1080×2400`。旧固定 `20×10` 网格使每格约 `54×240px`，因此“网格密度”失败；它不代表 ADB 或控件树失效。该次结果中 ADB 已连接，截图成功、XML 有 34 个可寻址候选、IME 前后保持一致。`ascii` 输入策略只证明基础回退可用，**没有证明中文输入可用**。

现在默认 `grid.mode: auto`：按实际截图宽高，以约 `100×110px/格` 计算列与行，再分别限制到 `5–26` 列、`3–40` 行。这台手机会得到 `11×22`，约 `98×109px/格`；`1920×1080` 车机的初始结果为 `19×10`。这些数字是基于像素尺寸的起点，仍需检查网格标签是否可读、点击误差是否可接受。

## `--check` 目前逐项做什么

| 输出项 | 实际检查 | 结果解释 |
|---|---|---|
| ADB 连接 | 解析目标设备 serial | 未授权、离线或多设备未指定时无法正常开始 |
| 型号、Android 版本 | 读取系统属性 | 帮助确认连的是目标设备；不是兼容性保证 |
| exec-out 抓帧 | 抓 PNG、解析实际宽高、记录耗时 | 截图无有效尺寸为硬失败；耗时 ≥2500ms 是速度警告 |
| 多屏提示 | 查询显示器列表 | 多屏时提醒核对截图是否为中控屏；仅看到设备在线不够 |
| 网格 | 按实际截图尺寸解析 `auto/manual`，计算单格宽高 | 超出建议的 `60–220px/格` 会警告，不阻断树路径 |
| uiautomator dump | 抓 XML、记录字节数和耗时 | 空 XML 是硬失败；耗时 ≥3000ms 是速度警告 |
| 可寻址候选 | 从 XML 提取可定位控件 | ≥3 个可走 tree；不足时主流程会走 VLM，故只警告 |
| 输入策略 | 顺序探测 `yadb → adbkeyboard → ascii` | 显示实际选中的策略；只有 `ascii` 时额外提示中文能力未证实 |
| IME 未被改坏 | 对比输入探测前后的系统输入法 | 不一致是硬失败，应先修复再跑中文任务 |
| 自检串行采集耗时 | 截图耗时加 XML 耗时 | 如实标为串行合计；主流程 `observe()` 另行并行抓取 |

`[✓]` 表示该检查通过，`[✗]` 表示设备硬故障，`[!]` 是速度、定位质量或待人工确认的警告。整体退出码只由硬故障决定。**`--check` 不调用模型 API**，因此通过不代表模型 URL、名称或 Key 正确。

旧版输出曾写“抓帧阈值 1500ms”，实际判断使用 2500ms；XML 3118ms 显示通过，却写“阈值 3000ms”；“单轮并行耗时”却使用两项之和。新版将 2500/3000/4500ms 用作速度警告，并更正了串行耗时文案。

## 网格设置的优先级

面板 `http://127.0.0.1:8777/settings` 的“手动设置网格”默认不勾选。此时内部 `grid.mode: auto`，每轮依据**当轮实际截图**计算；旋转屏幕后也会重新计算。勾选后内部变为 `manual`，列数与行数输入框才启用，保存的手动值优先于算法。`config.yaml` 中的 `cols/rows` 在自动模式下只是手动模式的备用值。

设置页尝试抓一张当前设备截图来显示自动建议和当前表单预计网格；设备离线时仍可保存设置，但不显示尺寸预览。保存后**新启动的任务**读取新配置；已运行的任务不会中途改网格。CLI 和面板任务共用 `config.yaml` 和同一计算函数。

## 模型设置与验证

设置页提供 URL、模型名称和 API Key。URL、名称及网格在重启后从 `config.yaml` 回显；密钥输入框始终留空，页面显示“已保存 / 环境变量 / 未配置 / 密文无法解密”的状态，留空表示保留现有凭证。新 Key 在 Windows 本机按项目 DPAPI 机制加密写入 `config.yaml`，换 Windows 用户或机器需重新录入。设置页及设置接口仅允许本机访问。

点击“验证连接”时，后端使用**当前表单中尚未保存的值**发起一次最小模型请求，返回成功/失败和耗时；该动作不保存配置、不连接 ADB，也不运行任务。失败应区分 URL/网络、鉴权、模型名和响应问题；错误不会回显 Key。保存和验证是两个独立动作。

## 仍需在设备上验证与后续优化

1. 手机竖屏 `1080×2400` 上查看 `11×22` 网格标签和点击落点；车机横屏对比自动 `19×10` 与旧手动 `20×10` 的识别效果。像素尺寸相近不等于模型识别率相同。
2. 多屏车机应肉眼确认截图来源，必要时设置 `display_id`；当前 `--check` 只提示多屏，不自动判断哪块是中控。
3. `ascii` 回退需要在明确允许输入的测试框中另测中文，不能通过自检结果推断中文搜索一定可用。
4. 可按真实日志统计截图、XML 和 GLM 延迟的分布，再决定速度警告阈值；当前阈值用于提醒，不代表比赛评分线。
5. 模型按钮必须在有网络和有效凭证的电脑上实测；离线测试只验证接口逻辑与密钥不回传。

从安装到任务拉通的完整命令见[部署与联调手册](部署与联调手册.md)。
