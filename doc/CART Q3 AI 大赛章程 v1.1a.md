## 四、课题：Automotive GUI Agent

### 4\.0 什么是 GUI Agent？

GUI Agent 是一种能\*\*"看懂界面、操作界面"\*\*的 AI Agent——它像人一样看屏幕上的图形界面（GUI，Graphical User Interface），理解当前状态，决定下一步动作，然后通过点击、滑动、输入完成任务。

**它和传统 Agent 的核心区别**：

- 传统 Agent 通过 **API 调用** 完成任务（结构化接口）

- GUI Agent 通过 **模拟人的操作行为** 完成任务（图形界面）

**为什么 GUI Agent 重要**：现实世界里 90% 的软件功能没有 API，只有 GUI。如果 Agent 能操作 GUI，它就能操作**任何有屏幕的软件**——包括车机、手机、PC。

**业内代表作**：

- Anthropic Computer Use（2024）—— 让 Claude 操作电脑

- OpenAI Operator（2025）—— 让 GPT 操作浏览器

- 字节 UI\-TARS / 上海 AI Lab OS\-Atlas —— 专门做 GUI 操作的开源模型

**本次课题要做的**：一个针对 **车机（Android Automotive）** 的 GUI Agent——让它自主操作车机屏幕，完成用户交给它的任务。

### 4\.1 课题目标

做一个能"看车机屏幕、操作车机屏幕"的 Agent——通过视觉理解界面，自主决策下一步操作，并通过 ADB 通道完成任务闭环。

### 4\.2 技术架构

为了保证大家能在规定时间内完成作品，组委会推荐采用 **PC / 车机分离** 架构（详细架构图见附页）：

\[CART\-Contest\-Architecture\-v1\.pptx\]

- **PC 端**：运行 Agent 大脑（LLM 决策、云端 VLM 调用、动作规划、状态管理），以及参赛队自行开发的 ADB 桥接层

- **车机端**：作为纯执行目标，通过 ADB 接收指令，返回屏幕图像与状态

- **通信通道**：ADB（`screencap` 抓帧、`uiautomator dump` 抓控件树、`input` 模拟操作）

**关键约定**：

- 车机侧**仅安装组委会指定的Bilibili、飞书、外卖，其余保持CEA1\.3原样**

- Agent 大脑在 PC 上运行，通过 ADB 与车机通信

- **场景强制限定** Android Automotive **主屏（中控屏）**——不支持多屏、副屏、仪表屏



### 4\.3 模型与 API（统一提供）

|能力|供应商|用途|
|---|---|---|
|视觉多模态（VLM）|**GLM 5\.3**（智谱）|图像理解、控件识别、坐标定位|
|语音识别（ASR，可选）|**讯飞开放平台**|语音任务输入|

**统一 API Key 由组委会在****组队完成后由VCPT发****放**。每队分配统一 quota。



**为什么这样定**：让所有队伍在同一起跑线上比拼 **Agent 闭环设计**——Skill 组织、Context 治理、Harness 设计、降级路径。这些才是本次比赛的核心考察点。模型能力建设由 **AI Lab 日常预研** 承载，不通过本次大赛承载。

### 4\.4 控件定位的三条技术路径

组委会推荐以下三条路径，参赛队伍**在验收标准里明确声明**选择哪一条：

|路径|说明|技术门槛|技术深度加分|
|---|---|---|--|
|**A\. 纯 VLM 定位**|整张截图 \+ 任务描述 → VLM 直接返回坐标|低|+0（基础赛道）|
|**B\. UIAutomator \+ LLM 混合**|`dump` 抓控件树 XML → LLM 从中选节点读坐标|中|+5|
|**C\. 控件树 \+ 视觉双兜底**|走 B，B 失败降级到 A|高|+10|

**技术深度加分说明**：路径 A 是**完整合规赛道**——做到极致同样有机会拿一等奖。路径 B / C 会获得**技术深度加分**（\+5 / \+10），因为课题作品未来将进入 CART OS Automotive GUI Agent 预研分支，架构深度关系到产品化能力。**加分不是门槛，是对深度挑战的奖励**——但 AI Reviewer 会核对声明路径与实际代码实现，虚报路径将按实际水平给分（声明 C 但实际是 B → 按 \+5 给；声明 C 但实际是 A → 按 \+0 给）。

**路径与孵化的关系**：走**路径 B 或 C**的作品优先纳入 CART OS Automotive GUI Agent 预研分支的孵化候选；走**路径 A** 的作品除非有明确的产品化亮点（场景选择、UX 设计、验收体系），否则主要进入 AI 骨干池和案例库。

### 4\.5 车机环境与参考任务

**车机预设应用**：

**基础应用（CEA1\.3 全套）**——所有 CEA1\.3 定义的座舱应用已预装，包括但不限于：导航、音乐、电话、消息、设置、电台、车辆控制、车辆信息、能耗等（完整清单以车机镜像为准）

**额外安装应用（3 个）**：

- **哔哩哔哩（B 站）** —— 视频类

- **飞书** —— 办公协同类

- **外卖** —— 生活服务类

**场景选择约定**：本次比赛所有任务场景**必须在以上应用范围内产生**。不接受"额外安装其他应用"或"操作系统级设置界面"作为主场景。

**三个参考任务**（供参赛队自评基线用）：

|难度|任务示例|说明|
|---|---|---|
|**简单（Easy）**|在音乐 App 里播放周杰伦的《七里香》|单应用、找歌 \+ 播放|
|**中等（Medium）**|打开美团外卖 App，搜索"兰州拉面"，把第一家店的招牌菜加入购物车|单应用、多步骤 \+ 状态判断|
|**复杂（Hard）**|收到飞书消息说"晚上 7 点会议"，把这个时间设为车机日程，同时在导航里把公司地址设为目的地|跨应用、含理解、含并行操作|

**说明**：这三个是**参考基线**，不是评审任务。**Demo Day 现场评委实测的任务**由评委另行准备（与参考任务同类型但内容不同），考察 Agent 泛化能力。参赛队伍可自选其他场景演示，但至少要能跑通**中等难度**级别的任务。

### 4\.6 语音输入（可选加分项）

- 允许接入讯飞 ASR 作为**任务入口**（用户语音一句话 → 转文字 → Agent 执行）

- **明确限制**：**只做语音输入**——禁止 TTS 输出、多轮语音对话、语音打断

- **架构原则**：语音是可插拔的感知通道，Agent 大脑不依赖它才能工作

### 4\.7 状态反馈（强制要求）

Agent 必须在 PC 屏幕**实时打印决策链**：

```Plaintext
[Step 1] 我看到了导航按钮 (置信度 0.87)
[Step 2] 决定点击坐标 (480, 320)
[Step 3] 点击成功,当前 Activity 已切换至 NavigationActivity
[Step 4] 我看到了搜索框...
```

**目的**：

1. 参赛队 Debug 手段

2. 评委可视化 Agent 内部推理过程（评审 Harness 设计的重要依据）

3. 训练"Agent 决策过程可观测"的工程直觉

## 七、评审标准（100 分制，二段式评审）（5 : 5）

本次评审采用 **"AI 客观 \+ 现场实测 \+ 人工主观" 三段式**，最大化公平性、透明性和实战性。

### 7\.1 客观评审（包含AI）（50 分）

由 **VCPT（Vibe Coding Pilot Team）开发的 AI Reviewer Agent** ，再结合人工Review，对交付物队形客观打分。**评审 rubric 和 prompt ****在9/20日****公开**——参赛队伍在开发过程中即可对齐标准。我们非常关注工程质量，包括以下几个方面

|子项|分值|说明|
|---|---|---|
|Harness设计|10|合适的Agent框架、成熟的失败回退机制、Agent的限制机制。|
|Skills/MCP|10|高质量、高效率、高准确率的skills 或者MCP|
|Context 组织、分层、经济性|10|极致的上下文压缩，每一个token都能产生经济效益|
|文档质量|10|文档不仅要有，还要追求高质量|
|代码质量|10||

> **备注**：工程质量维度**允许并鼓励使用 AI 辅助编码**（Cursor / Claude Code 等）。评审关注代码质量和架构清晰度，而非"是否人工手写"。

### 7\.2 现场评审（50 分，Demo Day）

评审对象:Agent 在真实车机上的表现

|子项|分值|判据|
|---|---|---|
|**环境搭建可复现性**|10|组委会指派专人按 README 从零搭建:10 分钟内跑通 = 5 ; 20 分钟 = 2;跑不通 = 0|
|性能|10|任务执行的速度快，响应快|
|稳定性|5|Demo运行稳定|
|准确率|15|执行任务的准确率|
|Demo效果及产品化程度|10<br>|UI交互是不是优秀？是不是更像一个好的产品|

### 7\.4 最终得分公式

```Plaintext
最终分 = 客观 50 + 现场主观评审 50  + 加分项
```

**加分项**（加分上限 \+18 分）：

|加分项|分值|说明|
|---|---|---|
|**技术深度加分**|**A: \+0 / B: \+****5**** / C: \+****10**<br>|按队伍声明的控件定位路径给分；**AI Reviewer 校验实际代码实现**，虚报按实际水平降级|
