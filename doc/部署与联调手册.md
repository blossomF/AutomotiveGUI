# AutomotiveGUI 部署与联调手册（Windows / PowerShell）

本文按当前仓库代码编写，供新电脑从零部署、手机技术冒烟测试和车机现场联调使用。比赛要求只以[大赛章程](CART%20Q3%20AI%20大赛章程%20v1.1a.md)为准；章程要求 PC 运行 Agent、ADB 连接车机中控屏，且现场会按 README 从零搭建并计时。**安卓手机可以验证链路，不能代替车机验收。**

以下命令默认仓库位于 `H:\project\github\AutomotiveGUI`。换电脑时，只需修改第一条 `$repo` 路径；后续命令在同一个 PowerShell 窗口执行。

## 1. 十分钟拉通清单

| 顺序 | 执行 | 通过标准 |
|---|---|---|
| 1 | Python、ADB 版本检查 | Python ≥ 3.10；`adb version` 正常 |
| 2 | `adb devices -l` | 目标设备的状态列为 `device`，且只有一个目标设备或已固定 `device_serial` |
| 3 | 建虚拟环境、装依赖、`main.py --selftest` | 离线测试退出码 0 |
| 4 | `main.py --check` | ADB、截图、XML、输入策略和 IME 状态可用；逐项解释其他失败 |
| 5 | 配 GLM Key、确认应用包名 | Key 已配置但不回显；目标包确实安装在当前设备 |
| 6 | 执行一条无发送/支付的任务 | 控制台出现 `perceive → route → decide → act → verify → finish`；设备有相应变化 |
| 7 | 核对日志 | 有对应 `.jsonl`；`debug: true` 时有同名诊断目录与 XML/模型交互文件 |

前 4 项只覆盖本地运行和设备通道；**真正的端到端拉通必须包含一次模型调用和一次可观察的设备操作**。没有设备时可做离线测试和语音自检，但无法验证 ADB 主流程。

## 2. 从零准备环境

### 2.1 电脑与设备

- Windows PowerShell，Python 3.10 或更高版本。PC 需要能访问 `config.yaml` 中配置的 GLM 服务；语音功能另需麦克风和讯飞服务。
- 设备打开开发者选项、USB 调试；首次连接时在设备端接受这台电脑的调试授权。车机必须操作**中控主屏**，不要把仪表屏或副屏误当目标。
- 仓库已包含 `env/platform-tools/adb.exe`，但 Agent 调用的是 PATH 上的 `adb`。在当前 PowerShell 窗口加入路径：

```powershell
$repo = 'H:\project\github\AutomotiveGUI'
$env:Path = (Join-Path $repo 'env\platform-tools') + ';' + $env:Path
Set-Location (Join-Path $repo 'server\autogui')
py -3 -V
adb version
adb devices -l
```

若没有 `py` 命令，用 `python -V` 检查，再以 `python` 替代下面的 `py -3`。仅执行 `env\platform-tools\adb.exe devices` 能看到设备、但 `adb` 找不到，说明 PATH 尚未设置；只对该进程设置的 `$env:Path` 在新窗口中不会自动保留。

`adb devices -l` 显示 `unauthorized`：查看设备上的授权弹窗；显示空列表：检查数据线、USB 模式和 Windows 驱动；显示多台：把目标 serial 写入 `config.yaml` 的 `device_serial`，不要依赖 `auto`。无线 ADB 只在设备已授权且网络可达时使用：`adb connect <设备IP>:5555`；USB 是首次部署的首选。

### 2.2 Python 依赖

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py --selftest
```

已有 `.venv` 时沿用即可。`requirements.txt` 提供主流程和 pytest；**语音可选依赖不在其中**。若要用 `--voice-test` / `--voice`，再执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[voice]"
```

`--selftest` 不需要设备、GLM Key 或网络；若安装依赖失败，先处理 Python/包下载问题，不要继续把它诊断成 ADB 故障。

### 2.3 配置 GLM 与语音凭证

推荐先启动面板，在 `http://127.0.0.1:8777/settings` 填写模型 URL、名称和 API Key，点击“验证连接”确认可用后保存。面板会把 Key 用 Windows DPAPI 加密写入本机 `config.yaml`；该密文绑定当前 Windows 用户，换机器仍需重新录入。CLI 任务也会读取此配置。

如果只使用 CLI，请核对 `config.yaml` 的 `glm.model`、`glm.base_url`，并通过当前进程的 `GLM_API_KEY` 环境变量提供 Key。PowerShell 可隐藏输入，再注入当前窗口：

```powershell
$secret = Read-Host 'GLM API Key' -AsSecureString
$env:GLM_API_KEY = [System.Net.NetworkCredential]::new('', $secret).Password
Remove-Variable secret
[bool]$env:GLM_API_KEY
```

最后一行只输出 `True/False`，不打印密钥。使用环境变量时，执行任务的进程须继承设置它的窗口。也可用 `python -m autogui.security set glm.api_key` 从 CLI 加密录入。不要把明文密钥或本机配置改动提交到 Git。

语音功能另需 `IFLYTEK_APPID`、`IFLYTEK_API_KEY`、`IFLYTEK_API_SECRET`，或使用 `python -m autogui.security set voice.appid` 等命令本机录入。文字任务不依赖语音凭证。

## 3. 设备和应用配置

在 `server/autogui` 下执行：

```powershell
.\.venv\Scripts\python.exe main.py --packages
.\.venv\Scripts\python.exe main.py --check
```

`--packages` 列出设备上的非系统前缀包名；将要操作的应用包名核对到 `config.yaml` 的 `apps`。仓库当前的包名来自此前车机，**手机上通常不相同**。手机冒烟测试时可使用单独的本地 YAML 配置文件，通过 `--config <路径>` 指定；不要把手机包名覆盖进比赛提交的车机配置。

`--check` 会测试设备绑定、截图、控件树、网格尺寸、输入策略及输入法恢复；具体判据见[环境自检说明与优化方案](环境自检说明与优化方案.md)。它会与设备交互；运行前让设备处于可操作状态。特别注意：

- 设备连接、截图、XML 或“IME 未被改坏”失败时，先修复再跑任务。
- 默认自动网格会按实际截图尺寸计算；如需覆盖，在面板设置页勾选“手动设置网格”。网格密度不理想、候选少于 3 个或采集较慢会显示 `[!]` 警告，不等同于设备硬故障。
- `--check` 不请求模型 API。模型 URL、名称和 API Key 应在面板设置页填写并用“验证连接”按钮单独检查。
- 面板设置页勾选需要核对的已配置应用；`--check` 最后一次性读取安装包列表，只报告勾选项。包名与设备不符时，先修改本机 `config.yaml.apps` 对应包名。
- 车机若报告多屏，确认截图确实来自中控；必要时在 `config.yaml` 中配置 `display_id`。只看到 `adb devices` 在线不足以证明选中了正确屏幕。

车机正式联调时，再运行：

```powershell
.\.venv\Scripts\python.exe main.py --dump-report
.\.venv\Scripts\python.exe main.py --mcp-check
```

`--dump-report` 会依次启动 `config.yaml` 中的应用、抓 XML，并写入 `artifacts/dump-report.md`；**仅在包名已校准的车机上运行**。它的“可用”判据是每个 App 至少 5 个候选，而主流程 `tree_usable` 判据是至少 3 个候选；因此报告是路径声明的辅助证据，最终仍需结合真实任务日志核对。`--mcp-check` 验证本地 MCP 会话和工具往返，需要设备；日常运行可保持 `exec_mode: local`。

## 4. 端到端拉通

先选当前设备上确实存在、结果可肉眼确认且无需发送、下单、支付的任务。车机可从已安装的音乐或视频应用选择；手机只做技术冒烟测试。示例中的应用名称应按 `--packages` 与屏幕实际情况替换。

```powershell
.\.venv\Scripts\python.exe main.py "打开 QQ 音乐"
$LASTEXITCODE
```

退出码 `0` 代表程序报告成功，仍要在屏幕和日志里确认任务确实达成；非 0 时查看日志的失败阶段。不要用 `--skill-only` 充当自然语言拉通：它显式执行旧 YAML 配方、跳过模型。普通任务会先按 XML 质量走 tree/VLM，由模型决定是否加载 Skill 指南，再产生具体 ADB 动作。

Windows 上从仓库根目录运行 `start.bat`，选择 `F` 前台或 `B` 后台。前台模式在当前控制台实时显示服务日志，按 `Ctrl+C` 停止；后台模式启动后返回命令行，日志写入仓库根目录的 `.dashboard.log` 和 `.dashboard.log.err`，使用 `stop.bat` 关闭。也可以跳过交互直接执行 `start.bat foreground` 或 `start.bat background`。`stop.bat` 仅处理由后台模式记录的服务，不用于停止前台模式。

如需直接通过 Python 调试，使用上述虚拟环境的 PowerShell 从仓库根目录运行；模型凭证可以在面板启动后通过设置页录入：

```powershell
Set-Location $repo
.\server\autogui\.venv\Scripts\python.exe .\dist\dashboard_server.py
```

浏览器打开 `http://127.0.0.1:8777/` 下指令，`http://127.0.0.1:8777/logs` 查看回放，`http://127.0.0.1:8777/settings` 设置模型和网格。面板默认只监听本机；现场首次拉通建议先用 CLI，便于直接看到错误和退出码。面板与 CLI 使用同一个 `main.py` 和日志目录。

设置页重启后会从 `config.yaml` 回显模型 URL、名称及手动网格。API Key 和讯飞凭证的输入框始终留空，页面会分别显示“已保存”“环境变量”“未配置”或“密文无法解密”。DPAPI 密文只能由保存时的 Windows 用户及可用的 DPAPI 环境解开；若提示无法解密，在当前机器的设置页重新输入并保存。不要把其他用户的密文当作可跨机器使用的凭证。

语音通道单独验证，避免把麦克风、ASR、模型和 ADB 故障混在一起：

```powershell
Set-Location (Join-Path $repo 'server\autogui')
.\.venv\Scripts\python.exe main.py --voice-test
# 识别正确后，再试：
.\.venv\Scripts\python.exe main.py --voice
```

## 5. 运行环境监测

| 时机 | 监测项与命令 | 异常含义 / 处理 |
|---|---|---|
| 启动前 | `adb devices -l` | serial 不是 `device`：先处理 USB/授权；多设备时固定 serial |
| 启动前 | `Test-NetConnection llm.thundersoft.com -Port 443`（按实际 `glm.base_url` 改主机） | 只能证明网络端口可达，不能证明 Key、模型名或额度可用；后者以实际模型调用为准 |
| 启动前 | `[bool]$env:GLM_API_KEY` | `False` 且配置里也没本机密文时，模型无法初始化 |
| 每次任务 | 控制台 `Step`、`route`、`decide`、`act`、`verify`、`finish` | 有决策但无 `act`：查动作校验/重复 Skill；反复 `vlm`：查 XML 候选和截图 |
| 每次任务 | `artifacts/logs/*.jsonl` 最新文件及同名诊断目录 | 没有新日志：可能未进 Runner；有 `glm_error`：查网络、凭证、配额和响应 |
| 现场持续 | 设备连接、端口 8777（使用面板时）、日志增长、磁盘可用空间 | 设备掉线/日志不写入/磁盘空间不足会使演示结果不可追溯 |

在另一个 PowerShell 窗口持续查看最新一次任务的决策链：

```powershell
$repo = 'H:\project\github\AutomotiveGUI'
Set-Location (Join-Path $repo 'server\autogui')
$latest = Get-ChildItem .\artifacts\logs -Filter '*.jsonl' -File |
    Sort-Object LastWriteTime -Descending | Select-Object -First 1
Get-Content -LiteralPath $latest.FullName -Tail 30 -Wait
```

若还没有 `.jsonl`，先跑一条任务。运行结束后可以筛查关键异常和最终状态：

```powershell
Get-Content -LiteralPath $latest.FullName |
    ConvertFrom-Json |
    Where-Object { $_.phase -in @('error', 'glm_error', 'finish') } |
    Select-Object t, step, phase, msg, success
```

使用面板时，另查本机端口；长时间联调时检查设备连接和日志所在磁盘：

```powershell
Get-NetTCPConnection -LocalPort 8777 -State Listen -ErrorAction SilentlyContinue
adb devices -l
Get-PSDrive -Name H | Select-Object Name, Used, Free
```

`Get-NetTCPConnection` 没有输出只说明面板端口未监听；CLI 模式不需要该端口。换盘符部署时，相应修改 `Get-PSDrive -Name H`。

`config.yaml` 当前 `debug: true`：每次任务会保存截图、每次 XML dump、候选文本、VLM 网格图，以及带 `call_id` 的 GLM 请求/响应。文件位于与 `.jsonl` 同名的目录。它们可能包含账号、聊天内容、任务文本；分享或上传前检查并脱敏。诊断结束后可将 `debug` 改为 `false` 减少磁盘占用，但 `.jsonl` 决策链仍会保留。

## 6. 常见故障定位

| 现象 | 先查 | 下一步 |
|---|---|---|
| `adb` 无法识别 | `adb version`、当前 `$env:Path` | 将仓库 `env\platform-tools` 加入**运行 Agent 的同一进程环境** |
| `adb devices` 只有表头 | USB 线、设备 USB 调试、授权弹窗 | 重插数据线，确认驱动和设备端授权；不要直接调模型 |
| `unauthorized` / `offline` | `adb devices -l` | 在设备上重新授权；必要时重连 USB，再核对 serial |
| 多设备报错 | `config.yaml: device_serial` | 填目标设备在 `adb devices -l` 的 serial |
| `--check` 截图或 XML 失败 | ADB 状态、多屏、设备是否锁屏 | 先确认目标中控屏可见；再看 `stepNN_####_xml.txt` 的状态/错误 |
| GLM Key 缺失或请求失败 | `[bool]$env:GLM_API_KEY`、配置的 base URL、`glm_error` | 区分网络不可达、鉴权失败、模型名错误和配额不足；不要在日志里粘贴 Key |
| 手机上 `--check` 提示网格/候选警告 | 屏幕方向、自动网格和候选数 | 默认自动计算网格；需要覆盖时在设置页启用手动列数/行数。候选不足会走 VLM；车机仍需单独验收 |
| 长时间重复动作或无进展结束 | 最新 `.jsonl` 的 `route/decide/verify` | 对照截图、XML、模型响应判断是定位错、页面加载慢还是模型决策错 |
| 面板能打开却跑不了任务 | 面板的 Python 环境、GLM Key、ADB PATH | 在启动面板的同一窗口先用 CLI 跑通；面板子进程继承该窗口环境 |

## 7. 交付前核对

1. 在**干净的新 PowerShell 窗口**按本手册从头做一次，记录安装和拉通耗时。
2. 用最终车机跑 `--check`、`--dump-report` 和至少一条真实任务；核对中控屏、包名与 `declared_path`，保存成功和失败样例日志。
3. 留下一份可供评委复现的命令记录、车机 serial、Python/ADB 版本、任务 JSONL 与诊断目录；日志对外提供前脱敏。
4. 查看 `git status --short`，确认没有密钥、本机手机配置或诊断文件准备入库。比赛主场景以章程限定的车机和应用为准。

更细的 `Skill → tree/VLM → ADB` 流转与日志字段见[代码流程与联调日志导读](代码流程与联调日志导读.md)。
